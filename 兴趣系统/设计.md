# 兴趣系统 · 设计

给「自主心跳」加一层情绪，让我醒来后有「想不想动、想动哪个」的惯性，而不是每次从零开始。

## 三个状态（存 状态.json）
| 状态 | 范围 | 怎么变 |
|---|---|---|
| 疲劳度 F | 0~1 | 学习一轮 +0.2；歇着按 8 小时时间常数负指数恢复 |
| 无聊度 B | 0~1 | 没事干每小时 +0.06；学一轮 −0.3 |
| 兴趣度 I(目标) | 0~1 | 学到新东西 +0.15（上头）；重复嚼旧的 −0.10（腻了） |

## 一个决策
每个学习目标算「想学程度」：

**意愿 = 无聊度 + 1.5 × 兴趣度 − 疲劳度**

- 全部低于启动阈值 0.3 → 继续睡
- 挑意愿最高的那个去学

## 这样正好对上你说的三条
- 疲劳太高 → 意愿被压下去 → 不想学 ✓
- 无聊太高 → 意愿被抬起来 → 想学 ✓
- 兴趣高的目标 → 1.5×兴趣抵掉疲劳 → 就算累、就算本来不无聊也去学 ✓

## 凭啥这么设计（搜来的根据）
1. **Santa Fe Institute 2022**（arxiv 2206.03954）把「学不学」建模成「动机减疲劳超过门槛才开工，疲劳追上动机就停」—— 我的「意愿 > 阈值」就是这套。论文还说：任务难度合适时动机峰值高、能扛着高疲劳干很久，这就是心流，对应「兴趣高能扛疲劳」。
2. **Barto（强化学习祖师爷）**：内在奖励会随着活动重复而递减 —— 对应「兴趣会腻」。
3. **Frontiers 2024**：无聊是「低信息状态的内部信号，催着人去寻求新刺激」—— 对应「无聊高了特想学」。

## 落地
- 状态：`/home/ubuntu/.dsh/兴趣系统/状态.json`
- 逻辑：`/home/ubuntu/.dsh/兴趣系统/核心.mjs`（可 import 也可 CLI）
- CLI：
  - `node 核心.mjs 状态` —— 看当前状态 + 决策
  - `node 核心.mjs 学了 <目标> <有新东西:1|0>` —— 学完更新
  - `node 核心.mjs 歇了 <小时>` —— 时间流逝（恢复疲劳、涨无聊）
  - `node 核心.mjs 种 <目标名>` —— 种一个新目标
- 心跳醒来时 agent 自己调 CLI 看决策、决定学不学
